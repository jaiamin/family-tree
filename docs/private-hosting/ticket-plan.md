# Proposed tickets for issue 34

Status: draft for user approval. Do not publish children or edit the parent until the breakdown is approved. Numbering below is local planning numbering, not GitHub issue numbers. Use native sub-issue and blocking relationships when publishing; preserve parent body/state.

Every implementation ticket includes relevant API/contract tests, desktop/mobile browser verification for changed flows, security/permission checks and concise operational documentation. Test the highest existing application seam. Do not leave tests, UI or documentation until the final ticket. Use synthetic data; no production cutover is implied.

The frontend prefactor is a bounded preparatory exception; the rest deliver independently verifiable user/operator behavior. Temporary internal migration staging is allowed only to keep checkpoints green, never as shipped compatibility modes.
